Build Kit

How this prototype is built

Every prototype starts from the same shared core. Skills tell the AI how we build. Checks catch what must never ship. This page is generated on every deploy, so it shows what actually ran.

The flow

  1. 1KickoffIn a new project the AI asks eight short questions first and writes the brief.
  2. 2SkillsClaude and Copilot follow the house rules and skills from the core.
  3. 3ChecksRun on commit, after the AI edits a file, and in CI before anything goes live.
  4. 4LiveEvery push to main is published here within about a minute.

Skills

Step-by-step know-how the AI picks up when the task matches. Written once in the core, used in every project.

Hooks

Small scripts that run at fixed moments while the AI works. They steer it without anyone having to remember.

When a session starts

Set up, then kickoff

Fetches the shared core and starts a local preview. New project: the AI is told to ask the kickoff questions before anything else. Existing project: it gets the brief, so nobody explains it again.

Before the AI edits a file

Brief first

The pages stay locked until the brief is written. The shared core can never be edited from a project.

After the AI edits a file

Check and fix

The preview rebuilds and the checks run straight away. If one blocks, the AI gets the reason back and fixes the cause itself.

Checks

The same plain scripts run in three places. Only CI is required. The others just tell you sooner.

  • git commitpre-commit hook
  • After the AI editsClaude hook, it fixes the cause itself
  • CI on every pushrequired, nothing goes live without it

See it catch something

What happens if someone, or the AI, tries to commit an API key and a real personal identity number.
